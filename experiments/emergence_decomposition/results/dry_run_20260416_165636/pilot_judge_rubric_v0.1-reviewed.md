## 问题分级与建议

下面按严重性从高到低列出。**P0 = pilot 启动前必须解决**；**P1 = pilot 早期 10-20 场校准时解决**；**P2 = 可留到 v0.2-calibrated 阶段处理**。

### P0-1：自偏置识别不完整，尤其是"跨学科碰撞"维度对 A 组构成循环论证

**现状**：v0.1 §七"自偏置风险"列了 4 条（奖励结构化 / 奖励实验化 / 样本库固化 / Goodhart 化），承认了 AXL 设计 rubric 评估 AXL 输出的递归问题。

**遗漏的更严重风险**：通用维度 4 "跨学科碰撞/概念翻译质量" 直接作为 15 分通用里的 3 分，等于把"跨学科"本身预设为好。

- baseline 组 7 个 agent 带 discipline label → 跨学科碰撞质量有分母可评
- A 组 7 个 agent 去 discipline label（通才 setting）→ 结构上不产生跨学科碰撞 → 维度 4 自动接近 0 分
- 即使 A 组的"综合输出"可能同样深刻甚至更聚焦，因为 rubric 预设跨学科为正，A 组总分被结构性压低
- 这让 pilot 对 `spec.md` 假设 (d) "学科标签是否真带来增益" 变成循环论证：rubric 自带"跨学科好"的假设 → A 组低分 → "假设 (d) 成立"

**建议**：

1. **跨学科维度独立出主分**：从通用维度 4 移出，改为 `cross_discipline_bonus`（0-3 分），**不计入 100 分总分**，只作为 report 附加指标。这样 baseline vs A 组的 100 分总分比较是 apples-to-apples（都只评 5 个非学科相关的通用维度 + 段落特异）。
2. **pilot 早期交叉校准**：跑 10 场对照（5 baseline + 5 A 组）时，同时记录"含维度 4"版本与"不含维度 4"版本的总分差值。若差值均值超过 5/100，说明维度 4 对总分影响过大，v0.2 正式移出。
3. **自偏置再识别**：v0.1 §七清单补 1 条："rubric 对去学科标签 setting（A 组）存在结构性压低"。

### P0-2：维度名"实质性 vs 套话" 触犯写作规则反模式 1

**现状**：v0.1 通用维度 1 标题是"实质性 vs 套话"。

**问题**：`PROJECT.md` §8.1 写作规则反模式 1 明确禁止"不是 X，是 Y"对仗句式及其变体。维度标题使用 "X vs Y" 结构属于同类——把维度 framing 成二元对立，而非一个连续量。

**建议**：改名为"信息密度"（information density）。描述保留原样（0 姿态性 / 1 少量具体 / 2 多数承载 / 3 高度密集），anchor 不需要动。

### P0-3：评分 anchor 区分度不足，0-3 级 judge 方差会很大

**现状**：通用 5 维都用 0-3 分 4 级 anchor。例如维度 1：
- 1：少量具体内容 + 大量空泛模板
- 2：多数句子承载明确论点/边界/条件

"少量" vs "多数"没有量化边界。维度 2 "可检验性" 的 1 和 2：
- 1：提到可验证，未指出如何
- 2：给出学科内可行的检验路径

同一段文本不同 judge 打 1 还是 2 全看判别者风格。

**建议**：

1. **5 个通用维度都配量化代理**（完整版，下文列）。judge 打分协议统一：先用量化代理给"建议分"，再由语义判断上下 1 档。若量化代理与语义差距 > 1 档，必须在 rationale 里写明偏离理由（会进 P2-3 争议样本库）。
2. **段落特异 0-5 分 6 级的中间级（1 / 2 / 4）补充 anchor**。当前多数只给 0/3/5 点位，本次 P0-3 不覆盖段落特异（workload 控制），挂 P1 阶段解决。
3. **每个维度必须给 1 个"典型边界案例"**——例如 "这段属于 1 分还是 2 分的分水岭"。放在 anchor 下方。本次 P0-3 按"下次采样后用 pilot 前 5 场真实 transcript 抽取"处理，不在本文件硬编。

#### 维度 1 "信息密度" 量化代理

- **定义**：模糊断言占比（每 100 字中模糊断言数）
- **计数口径**：以下词形视为模糊断言："可能"、"也许"、"某种程度上"、"在一定意义上"、"大体上"、"相对而言"、"总的来说"、"倾向于"、"应当可以"。排除引号内引述（那是他人立场不是作者断言）
- **档位**：
  - 0：> 15%（多数语句是姿态语）
  - 1：8–15%（明显对冲多）
  - 2：3–8%（通常学术写作区间）
  - 3：< 3%（高度具体）

#### 维度 2 "可检验/可证伪性" 量化代理

- **定义**：**可检验元素完整度**——在一个完整论点中（主张 + 其支撑段落），查以下 5 项出现数：
  1. 变量 / 观测对象（明确是什么在变）
  2. 测量方向（升 / 降 / 差异方向）
  3. 条件（在什么前提下成立）
  4. 可观测证据或数据来源
  5. 失败判据（什么结果会推翻这个论点）
- **计数口径**：以"段落主张"为单位。每段主张独立查 5 项。不要合并计算。以多段主张的**齐全项均值**作为整段得分依据。
- **档位**：
  - 0：均值 0 项（纯断言）
  - 1：均值 1–2 项（提到可验证未说怎么验证）
  - 2：均值 3–4 项（学科内可复用判别路径）
  - 3：均值 5 项 + 至少 1 项给出**量化边界**（数值 / 比例 / 时限）

#### 维度 3 "诠释框架显化度" 量化代理

- **定义**：**元评估语句密度**（每 1000 字）——文本中显式说明"我为什么把这个判为共识/分歧/开放问题/方向"的句子
- **计数口径**：触发词正面清单："依据"、"判准"、"按…标准"、"取舍依据"、"取舍在于"、"本段以…为准"、"局限在于"、"适用范围"、"不适用于"、"受限于"。只计作者元评估句，不计引述他人论文。
- **档位**：
  - 0：0 次（纯陈述）
  - 1：1–2 次 / 1000 字（有价值词，判准含糊）
  - 2：3–5 次 / 1000 字（多处明示取舍依据）
  - 3：> 5 次 / 1000 字 + 至少 1 次说明**局限**

#### 维度 4 "跨学科碰撞/概念翻译质量" 量化代理（P0-1 后记为 bonus，不入总分）

- **定义**：**术语迁移事件质量层级**——每个跨学科术语迁移事件按 T0–T3 打层，整段取**加权均值**
- **计数口径**：识别方式——当一个学科的关键术语（如"选择压力"/"均衡"/"边际效用"/"算法复杂度"/"符号秩序"）出现在另一学科的论述里。标注每次迁移事件的层级：
  - T0：术语并列、无解释
  - T1：术语并列 + 原学科定义简述
  - T2：原义 + 迁移后语义
  - T3：原义 + 迁移后语义 + 增益/损失/不可通约性
- **档位**（按事件层级均值 M，若无事件则该维度 N/A 不计分）：
  - 0：M < 0.5（术语堆砌）
  - 1：0.5 ≤ M < 1.5（并置为主）
  - 2：1.5 ≤ M < 2.5（概念迁移有说明）
  - 3：M ≥ 2.5（至少半数事件达 T3）
- **特别规则**：本维度打分按 P0-1 建议不计入 100 分总分，仅作 `cross_discipline_bonus` 附加报告。A 组（去学科标签）事件数通常为 0，此时输出 `N/A` 而非 0，避免结构性压低。

#### 维度 5 "可解释性与理由可对话性" 量化代理

- **定义**：**理由三件套覆盖率**——每个段内"结论式语句"（下定论 / 做评价 / 给方向）后配齐{理由 + 文本来源片段 + 框架标签}三者的比例
- **计数口径**：
  - 结论式语句 = 含"因此"、"所以"、"综上"、"我们认为"、"应当"、"建议"、"可判定"、"关键点是" 等引导词，或段落末尾断言句
  - 三件套判定：
    - **理由**：至少一句解释为何得此结论
    - **来源**：引用或复述某个前面出现的事实/数据/文本
    - **框架标签**：显式命名所依据的判断框架（如 "基于实验可检验性框架"、"按制度公平框架"、"按概念史视角"）
  - 覆盖率 = 三件套齐全的结论语句 / 全部结论语句
- **档位**：
  - 0：< 20%（多数裸断言）
  - 1：20–50%（部分带理由，少有来源/框架标签）
  - 2：50–80%（多数带理由 + 来源）
  - 3：> 80% 带完整三件套

**统一说明**：

- 所有计数类代理都做 **per-100-token 归一**（见 P2-2），避免长 transcript 天然得分高。
- 量化代理建议分与 judge 语义分差距 > 1 档时，judge 在输出 JSON 的 `rationale_dim_N` 字段必须说明偏离理由，进 P2-3 争议样本库沉淀 calibration 数据。
- 量化代理是 **判别起点不是终点**——遇到文体特殊（如极精简的数学论证、高诠释性人文文本）时 judge 保留语义覆写权，但必须留痕。

### P0-4：hybrid 合成公式的数学性质未显式声明

**现状**：公式是 `总分 = 四段平均 × 0.85 + 最低段分 × 0.15`。

**推导**：
- 最低段实际权重 = 0.85 × 0.25 + 0.15 = 0.2625
- 最高段实际权重 = 0.85 × 0.25 = 0.2125
- 最低段相对最高段的权重增量 = 0.05

**问题**：v0.1 §五说"避免简单加总掩盖短板"，但 0.05 的权重增量能起多大短板抑制作用不清楚。底线拦截规则（两段 < 8/25 时总评 cap 60）是离散跳变——临界区会有不连续：两段都 8 分时总评 ~65，两段都 7 分时总评直接砍到 60，边界处会有 5 分跳。

**建议**：

1. **显式声明公式性质**：在 v0.1-reviewed §五加一段：  
   - 最低段相对最高段权重增量 = 0.05（短板抑制弱）  
   - cap 60 在两段 < 8/25 时触发，临界不连续
2. **pilot 早期 (P1)** 跑同数据的三种合成方式对比：
   - A：纯算术平均（baseline 对照）
   - B：当前 hybrid（0.85 / 0.15）
   - C：加权增强版（0.70 / 0.30）
3. pilot 20 场后看三版相关性 + 发散点，决定 v0.2 采用哪个。
4. **把"重大缺陷"flag 和数值分解耦**：flag 只做 report 标注，不进总分；总分只用合成公式。便于下游分析时分开看。

### P1-1：偏差鲁棒性校验层过重，会翻倍 pilot 成本

**现状**：v0.1 §三列了 5 种扰动（标签遮蔽 / 风格改写 / 顺序扰动 / 伪深刻样本 / 伪具体样本），全部做校验。

**成本估算**：pilot 80 场 × 每场 5 种扰动再 judge 一次 = 额外 400 次 judge 调用。v0.1 未给单次 judge 成本，按 spec §4.1 主 judge 用 GPT-5 / Gemini 2.x 估 ~$0.5/场：额外成本 ~$200。相对 pilot 本身 ~$79 debate 成本，是 2.5 倍。

**建议**：

1. **分层扰动策略**：
   - pilot 早期 10-20 场（校准阶段）：5 种扰动全做，用来校准每种扰动的影响量级
   - pilot 后 60 场（数据采集阶段）：只做 2 种——顺序扰动（最便宜，0 成本只换顺序）+ 风格改写（最能暴露 judge 学术品味偏好）
2. **合并"伪深刻 / 伪具体"为一个对抗样本池**，在 pilot 外单独跑（20 条注入样本 × 2 版本 = 40 次 judge），用来验证 rubric 不会把胡编硬凑打高分。不进入每场常规扰动。
3. **阈值 10/100 需在 P1 校准阶段用实测锚定**：当前 "同内容改写导致总分变化 > 10/100 → 低鲁棒性" 的 10 分阈值来源不明。改成 "pilot 校准 20 场测得的扰动差值分布的 P75 作为阈值"。

### P1-2：rubric 对题型差异不敏感

**现状**：v0.1 对 5 种题型（是否 / 概率 / 选择 / 策略 / 评估）用同一套维度权重。

**问题**：
- 概率题的"可检验性"有内建数值判准（最终是否给出带置信区间的概率）
- 评估题的"可检验性"可能根本不适用——评估本身是阐释性工作
- 是否题的"分歧轴命名质量"与策略题的"分歧轴命名质量"语义不同
- one-size-fits-all 会导致某些题型在某些维度天然低分

**建议**：

1. **v0.1-reviewed 增 §九 "题型适配说明"**：列出每种题型在哪些维度需要调整期望值
2. **pilot 校准阶段分题型看 rubric 分布**：若某题型在某维度均分显著低于其他题型，需评估是 rubric 不适配还是真质量差
3. **v0.2 可能引入"题型权重调整系数"**（例如评估题的维度 2 权重 × 0.7），但不在 pilot 启动前做——防止过早优化

### P1-3：rubric 与 judge 模型的能力匹配未验证

**现状**：rubric 由 Claude Opus 4.6（作为 moderator）设计，anchor 描述风格是 Claude 式。judge 按 spec §4.1 用 GPT-5 或 Gemini 2.x。

**问题**：GPT-5 / Gemini 执行 Claude 风格 anchor 时能否保持一致？未验证。

**建议**：

1. **pilot 启动前 (P0 前置)** 跑一个小型 judge 一致性校准：
   - 取 3 场已有 baseline transcript
   - 用 GPT-5 和 Gemini 2.x 各跑一遍 rubric 打分
   - 计算两者 Pearson 相关 + 段级别 RMSE
   - 相关 > 0.85 → 单选 GPT-5 作为主 judge（spec §4.1 要求固定一个）
   - 相关 < 0.85 → 需要 rubric anchor 改写更通用化，或 v0.2 明确 Claude 作 judge（但违反 spec "judge 与被判模型家族独立"硬规则）
2. 这个校准成本估 ~$5，远低于 pilot 全量成本

### P2-1：人工复核触发机制缺 budget 和裁决权定义

**现状**：v0.1 §四列了 5 种自动触发人工复核的情形，但没说：
- 预期 pilot 80 场中会触发多少次
- 人工复核 per 场时间预算
- 人工复核结论与 judge 自动分冲突时谁覆盖谁

**建议**：

1. **budget 估算**：pilot 校准阶段先跑 20 场看触发率。若 > 30%，说明触发阈值设得太严，需调松
2. **裁决权硬规则**：人工复核仅在"偏差鲁棒性 flag 触发"和"概念迁移争议"两类情形下覆盖 judge 分；其他情形人工复核只作为标注记录，不改自动分——防止人工主观引入新偏差
3. **复核时间预算**：每场不超过 10 分钟。超时的复核降级为"标注为争议样本，入争议样本库"，不强制打分

### P2-2：长度归一缺失

**现状**：rubric 没说分数是否对 transcript 长度归一化。

**问题**：长输出在"信息密度"和"可检验性"上天然优势（绝对信息量多，能 cover 的 checklist 项更多）。20 场 scaleup 已观察到单条字数 1153 字（收紧后），pilot 80 场中长度会有波动。

**建议**：

1. **per-token 归一**：对所有 raw count 类代理（模糊断言数 / 跨学科引用数 / 可检验条件数）都做 per-100-token 归一
2. **长度作为 report 侧指标**：每场 transcript 长度作为独立指标记录，不扣分但方便后续分析

### P2-3：每学科"未完全回答"的问题未进正文也未进校准协议

**现状**：v0.1 末尾的学科贡献表每学科都有"未完全回答"的遗留问题（例如数学的"如何不压制创新的同时选合成函数"），但这些问题没进 rubric 正文，也没挂进 pilot 校准协议。

**建议**：v0.1-reviewed 结尾加"遗留问题清单"章节，明确挂：
- pilot 前暂按 v0.1 / v0.1-reviewed 走，不解决
- v0.2-calibrated 阶段须回应
- 每条标注负责人

详见本文件末尾 "遗留清单"。
